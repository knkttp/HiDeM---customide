## 1. Project Overview

**HiDeM** is a standalone, frameless Windows Desktop IDE (`HiDeM.exe`) built with **Electron + React 18 + TypeScript + Vite + TailwindCSS + Monaco Editor + Express Compiler Engine**.

### Key Capabilities
- **5 Supported Languages:**
  - **C++17:** `g++ -O2 -std=c++17` (compiled once per run, executed sequentially against each test case with a `3000ms` TLE limit).
  - **Rust:** `rustc -O` (compiled to native binary, executed sequentially per test case with `3000ms` timeout).
  - **Python 3:** `python -u` (unbuffered execution per test case with `3000ms` timeout).
  - **HTML5:** Real-time Live DOM Sandbox rendered inside `<iframe sandbox="allow-scripts">`.
  - **JSON:** Syntax validation (`JSON.parse` / `JSON.stringify`), Prettify (2 spaces), Minify, and exact `Line` / `Column` error reporting.
- **3-Layer Wallpaper & Real-Time Frosted Glass Blur:**
  - Layer 1 (`z-index: 0`): Custom Wallpaper (URL or uploaded local Base64 image).
  - Layer 2 (`z-index: 1`): Real-time CSS `backdrop-filter: blur(var(--blur-px))` (`0px` to `30px`) + adjustable overlay opacity (`0.15` to `0.95`).
  - Layer 3 (`z-index: 2`): Transparent Monaco Editor & Auto-Judge UI (`background-color: transparent !important`).
- **5 Built-In VSCode Color Themes:**
  - `one-dark-pro`, `dracula`, `monokai-pro`, `github-dark`, `solarized-light`.
- **Multi-File Tab System & Native In-App File Dialogs:**
  - VSCode-style multi-tab bar supporting multiple open files across different languages simultaneously.
  - Double-click tab name to rename (auto-detects language from file extension).
  - Unsaved changes indicator (`●`).
  - **`Ctrl + O`**: Opens native Win32 modal Open File dialog parented directly to the Electron `mainWindow` (supports multi-file selection).
  - **`Ctrl + S`**: Saves directly to disk without opening a dialog if `filePath` is already linked; otherwise opens the parented Save File dialog.
  - **`Ctrl + Shift + S`**: Always opens the parented Save As dialog.
- **Customizable Starter Code Templates:**
  - Built-in **Templates Manager** (`TemplateModal.tsx`) allowing users to edit, save, reset, or insert starter templates per language.

## 4. Architecture & Data Flows

### 4.1. Desktop Launch Flow (`HiDeM.exe`)
1. User double-clicks `HiDeM.lnk` on Desktop (or runs `HiDeM.exe`).
2. `launcher/main.cpp` locates `node_modules/electron/dist/electron.exe` and spawns `electron.exe electron/main.cjs` with `CREATE_NO_WINDOW`.
3. `electron/main.cjs` checks if `http://127.0.0.1:5000/api/health` is alive. If not, it spawns `dist-backend/server.cjs` as a hidden background child process (`ELECTRON_RUN_AS_NODE=1`).
4. `electron/main.cjs` creates a frameless `BrowserWindow` (`frame: false`) loading `http://localhost:5000` (which serves `dist/index.html` and `/api/execute`).
5. When the user closes the window, `window-all-closed` kills `backendProcess` and exits cleanly.

### 4.2. Electron IPC Contract (`window.hidemDesktop`)
Defined in `electron/preload.cjs` and handled in `electron/main.cjs`:
- `window.hidemDesktop.isElectron: boolean`
- `window.hidemDesktop.minimizeWindow(): void`
- `window.hidemDesktop.toggleMaximizeWindow(): void`
- `window.hidemDesktop.closeWindow(): void`
- `window.hidemDesktop.openFilesDialog(): Promise<{ canceled: boolean, files: Array<{ name, filePath, language, content }> }>`
  - Uses `dialog.showOpenDialog(mainWindow, { properties: ['openFile', 'multiSelections'] })` so the file dialog is a child modal of `mainWindow`.
- `window.hidemDesktop.saveFileDialog({ suggestedName, content, language }): Promise<{ canceled: boolean, filePath?, name?, language? }>`
  - Uses `dialog.showSaveDialog(mainWindow, ...)` and writes the file to disk.
- `window.hidemDesktop.saveFileDirect({ filePath, content }): Promise<{ saved: boolean, filePath, name }>`
  - Writes directly to `filePath` via `fs/promises.writeFile` without showing any dialog.

### 4.3. LocalStorage Persistence Keys (`src/App.tsx`)
- `custom_ide_theme_config_v1`: `{ wallpaperUrl, blurPx, opacity, theme }`
- `custom_ide_custom_templates_v2`: `Record<'cpp' | 'rust' | 'python' | 'html' | 'json', string>`
- `custom_ide_open_tabs_v2`: `Array<CodeFileTab>` (`{ id, name, language, code, filePath?, isDirty? }`)
- `custom_ide_active_tab_id_v2`: Active tab `id` string
- `custom_ide_test_cases_v1`: `Array<TestCase>` (`{ id, input, expectedOutput, actualOutput, status, timeMs }`)

## 5. Build, Development & Debugging Commands

> **Note for PowerShell on Windows:** Ensure Node.js and WinLibs `mingw64\bin` are in `$env:PATH` during terminal sessions:
> ```powershell
> $env:PATH += ";C:\Program Files\nodejs;$env:APPDATA\npm"
> $winlibsBin = (Get-ChildItem "$env:LOCALAPPDATA\Microsoft\WinGet\Packages\BrechtSanders.WinLibs*" -Directory | Select-Object -First 1).FullName + "\mingw64\bin"
> $env:PATH = "$winlibsBin;$env:PATH"
> ```

### Run in Development Mode (Hot Reload)
```powershell
npm.cmd run dev
```
- Starts `tsx watch src-backend/server.ts` on `http://localhost:5000` and Vite dev server on `http://localhost:3000`.

### Build Production Bundles & Rebuild `HiDeM.exe`
Whenever you modify any file in `src/`, `src-backend/`, `electron/`, or `launcher/`, run:
```powershell
npm.cmd run build:exe
```
What `npm run build:exe` does under the hood:
1. `npm run build` (`tsc && vite build` $\rightarrow$ outputs frontend to `dist/`).
2. `npm run build:backend` (`esbuild src-backend/server.ts --bundle --platform=node --format=cjs --outfile=dist-backend/server.cjs`).
3. `g++ -O2 -std=c++17 -static -mwindows launcher/main.cpp launcher/app.res -o HiDeM.exe -lws2_32 -lshell32 -lole32`.

*(If you change `launcher/app.ico` or `launcher/app.rc`, recompile the resource first via `cd launcher; windres app.rc -O coff -o app.res; cd ..` before running `npm.cmd run build:exe`.)*

## 6. Common Extension Points for Future

1. **Adding a New Programming Language (e.g., Java, Go, JavaScript):**
   - Add a new runner in `src-backend/runner/<lang>Runner.ts` using `runProcessWithInput` from `cppRunner.ts`.
   - Register the language route in `src-backend/server.ts` (`/api/execute`).
   - Add the language key to `SupportedLanguage` and `LANGUAGE_META` in `src/components/TopBar.tsx`.
   - Add a default template in `FACTORY_CODE_TEMPLATES` in `src/App.tsx`.
   - Register Monaco completion snippets in `registerIntelliSenseProviders` inside `src/components/EditorPane.tsx`.
2. **Adding Custom Time / Memory Limits:**
   - Currently hardcoded to `3000ms` (`timeoutMs = 3000`) in `cppRunner.ts`, `rustRunner.ts`, and `pythonRunner.ts`. Pass `timeLimitMs` in the `/api/execute` request body to make it configurable from the UI.
3. **Diff Highlighting (Character/Line Diff):**
   - `TestCasePane.tsx` currently displays `Expected Output` and `Actual Output` side-by-side. You can integrate Monaco's `<DiffEditor />` or line-by-line diff highlighting when `tc.status === 'WA'`.
